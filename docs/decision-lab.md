# Лаборатория решений

Отличительная возможность проекта — связать исследование с развилкой действия: «что нужно увидеть, чтобы выбрать другой путь?» Агент формулирует сценарии и возражения, Python прозрачно проверяет арифметику, человек решает. Численный расчёт необязателен, если качественное сравнение честнее.

## Что можно увидеть за минуту

Откройте `examples/decision-lab/exports/decision-lab.html`. Переключите «Широкий спрос» и «Расходы недооценены»: условный выбор меняется с масштабирования на закрытие. Вернитесь ко всем сценариям: ограниченный пилот имеет меньшую худшую цену ошибки в этой учебной матрице. Ни один вариант не объявляется истинно лучшим для бизнеса.

В `exports/lab-replay.json` сохранена более существенная поправка: в идеальной диагностике проверка ценой 12 000 условных RUB снижает границу ошибки с 40 000 до 12 000. После добавления возможного неубедительного исхода граница с расходами становится 52 000. Агенту запрещено обещать гарантированную пользу такого исследования. Возможная польза не равна нулю; отсутствуют данные для её вероятностной оценки.

Это авторская числовая иллюстрация, а не реальные деньги, подтверждённый спрос, экономия компании или сравнение с живым аналитиком. Сами числа не выведены из учебных когорт. Оценка нуждается в содержательной проверке человеком.

## Метод

Для допустимого действия a и сценария s задаётся U(a,s) — сопоставимая полезность на одном горизонте. Больше лучше. Предварительно исключаются варианты, нарушающие жёсткие ограничения. После исключения:

```text
best(s) = max по допустимым a: U(a,s)
regret(a,s) = best(s) - U(a,s)
R(S) = min по a: max по s из S: regret(a,s)
```

Это minimax regret по конечному набору сценариев. Ничьи сохраняются. Вероятности не назначаются; метод консервативен и не заменяет предпочтения владельца риска. Добавление одинаковой константы ко всем действиям внутри сценария не меняет regret.

Проверка t задаёт возможные наблюдения o и совместимые с ними множества сценариев S(t,o). Они должны покрывать весь исходный набор и могут пересекаться. Неубедительный исход обычно совместим со всеми сценариями. Для заранее заданной политики выбора после наблюдения:

```text
residual(t) = max по исходам o: R(S(t,o))
bound(t) = residual(t) + cost(t) + delay_cost(t)
reduction(t) = R(S) - bound(t)
```

Здесь oracle — лучшая допустимая стратегия в исходном сценарии без оплаты исследования. Поэтому стоимость добавляется к остаточной цене ошибки, а не исчезает при сравнении вариантов. Кандидат исследования должен вписаться в бюджет и строго уменьшать границу. Это вычисленная условная гарантия в заданной модели наблюдений; не Expected Value of Information, не прогноз ROI и не оценка реальной точности метода исследования. Произвольное исключение неудобного исхода делает модель необоснованной, даже если JSON проходит валидацию.

## Запуск и хранение

```text
python -X utf8 demo/lab.py projects/lab-demo
python -X utf8 -m strategist lab show projects/lab-demo
python -X utf8 -m strategist lab analyze projects/lab-demo/lab-input/idealized.json
python -X utf8 -m strategist lab analyze projects/lab-demo/lab-input/with-inconclusive.json
```

Новый реальный проект сначала проходит обычные brief/research/options. Скопируйте форму модели из примера, заменив все сценарии, оценки и ID. Затем:

```text
python -m strategist lab commit projects/case projects/case/lab.json
python -m strategist lab export projects/case
```

Поля `metric_definition`, `horizon`, `coverage_limits`, `payoff_rationale` объясняют шкалу и допущения. `claim_refs` ссылаются на действующие выводы, а не подтверждают величины. У каждого сценария `falsifier`; у проверки `cost_basis`, `duration`, `limitations`, `outcomes`. Все цены в одной единице. Допустимы RUB/USD/EUR либо явно согласованные utility_points. Нельзя складывать часы и рубли без объяснённой оценки перевода. `constraints` и `violations` задаются содержательно; программа не определяет соответствие юридическим или бизнес-требованиям.

Lab хранится отдельно от источников в `state.decision_lab` и неизменяемом blob; события содержат хеш текущей и прежней версии. Файлы новой версии не меняют старые артефакты. Изменение исходных документов, отзыв или добавление источника делает анализ устаревшим. Повторный commit одинакового актуального ввода идемпотентен. Новый анализ снимает старое одобрение решения. Возобновление показывает его статус; read-only MCP `strategy_lab` возвращает проверенный снимок. Обычный export блокируется при устаревшем расчёте. Черновой export заменяет старую интерактивную страницу явным сообщением о пересмотре.

## Проверка метода и границы

`tests/test_decision_lab.py` проверяет сравнение с независимым полным перебором политик для 30 воспроизводимых случайных матриц, пересекающиеся исходы, бюджет и задержку, ничьи, ограничения, запрет ложной фактичности чисел, инвалидацию, повторный запуск, MCP и HTML escaping. Такой математический oracle независим от реализации решателя, но это не независимая LLM или эксперт.

Нельзя заявлять «агент лучше обычного чата на 62%» из сравнения 105 000 и 40 000 условных RUB: baseline здесь — явно заданное правило выбора по одному сценарию. Минимакс выигрывает в собственной целевой функции по определению. Практическая польза — обнаруженная хрупкость решения и неработающая гарантия исследования, которую можно воспроизвести и оспорить.

## Методологическая связь

Минимакс сожаления и выбор информативных вопросов — известная область поддержки решений: Wang & Boutilier, [Incremental Utility Elicitation with the Minimax Regret Decision Criterion](https://ijcai.org/proceedings/2003/46), IJCAI 2003. Наш инструмент реализует небольшой конечный сценарный вариант и авторскую проверку стоимости наблюдения; он не воспроизводит все алгоритмы статьи и не присваивает её эмпирические результаты.
