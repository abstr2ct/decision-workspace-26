# Версия 0.5: меньше служебной работы, понятнее выбор

Завершённый живой прогон показал недостаток: агент v0.3 затратил 307,64 секунды против 179,17 секунды обычного чата; превосходство качества не установлено. Вместо добавления новых моделей исправлен конкретный источник накладных расходов — сохранение большого числа подготовленных артефактов и повторное изложение тех же оснований.

## Что изменилось

- `checkpoint` принимает готовые claims, research, options и proposal одним JSON. Все существующие валидаторы сохраняются. Только после их успеха исходный state получает одну новую ревизию. Ошибки, пауза, устаревшая ревизия и повторная попытка обработаны отдельно. Подтверждение решения человеком в посылку не входит.
- `decision-card` формирует компактный снимок для владельца: вопрос, рекомендация, сильные возражения, условия пересмотра, неизвестное, альтернативы и источники. Ожидающее согласования предложение показывается до одобрения бизнес-действия. Другие ошибки целостности блокируют выдачу.
- Инструкция агента предлагает использовать эту карточку вместо создания второго независимого длинного отчёта по тем же данным. Исследование и сложность решения остаются предметом работы LLM.

## Измерено локально

Одинаковая подготовленная посылка: 6 claims, research, options, proposal. Три повтора каждого способа, порядок чередуется. Содержательные хеши результатов совпадают, решение не подписано за владельца.

| Показатель | Отдельные команды | Checkpoint |
| --- | ---: | ---: |
| Вызовы CLI | 9 | 1 |
| Медиана технического времени, с | 1,620 | 0,295 |
| Медиана stdout, UTF-8 байтов | 15 827 | 274 |

Это уменьшение служебного вывода примерно на 98,3%. Замер CLI исключает рассуждение LLM, подготовку материалов, интерфейс и работу человека. Он НЕ показывает, что полное решение теперь создаётся за 0,295 с или что устранена вся разница 128 с. В старом прогоне несколько CLI могли выполняться внутри одной shell-команды; количество CLI не равно количеству обращений к модели. Полный живой прогон v0.5 ради экономии лимитов не проводился.

Данные: checkpoint-benchmark.json; воспроизведение: `python tools/benchmark_checkpoint.py`. Ограничение масштабирования — копирование blobs для изолированной проверки. Крупные проекты могут получить иной результат.

## Демонстрация для жюри

Откройте examples/owner-review/exports/decision-card.html. В основе — сохранённое состояние первого завершённого LLM-прогона на синтетической «Смене», новая карточка создана без повторного вызова модели. Видно, что бизнес-решение ещё на согласовании. Раскройте источники, затем на копии проекта отзовите источник: формирование новой карточки остановится до пересмотра.

Этот переход от исследовательского основания к решению и его отзыву — проверяемая возможность. Уникальность среди всех конкурсантов, максимальные баллы и победа не установлены. Число дополнительных компонентов не используется как доказательство качества.

Проверки: 86 тестов в verification-v0.5.json; rollback при поздней ошибке и сбое диска, идемпотентность, защита согласований, stale state, экранирование HTML; карточка проверена в браузере на desktop и 390 px.
