# Сохранить подготовленный этап и показать выбор владельцу

Когда бриф подтверждён, материалы импортированы и анализ выполнен, агент может сохранить несколько подготовленных артефактов одной командой. Новый инструмент не выполняет исследование вместо модели и не принимает решение за владельца.

```text
python -m strategist resume projects/case
python -m strategist checkpoint projects/case prepared.json
python -m strategist decision-card projects/case
```

Форма prepared.json:

```json
{
  "base_revision": 12,
  "claims": [],
  "research": {},
  "options": {},
  "proposal": {
    "option_id": "focus",
    "rationale": "Условная рекомендация с основаниями",
    "claims": ["claim-id"]
  }
}
```

Уберите отсутствующие необязательные поля; пустые research/options нужно заполнить по обычным шаблонам, иначе валидация остановит сохранение. base_revision — фактическая текущая ревизия из resume, не число из примера. Можно отправить только claims либо только готовые документы. Максимум 100 claims и 8 MiB JSON. Источники импортируются отдельно. Ключи approvals, команды shell, пути импорта и внешние действия не поддерживаются.

Временная копия проверяется существующими валидаторами под блокировкой записи. В исходном проекте фиксируется одна новая ревизия только после успеха всех шагов. Ошибка последнего шага не оставляет наполовину сохранённые claims/research/options. Повтор той же последней успешно сохранённой посылки идемпотентен; если состояние уже изменилось, нужно получить новую ревизию и согласовать изменения, а не перезаписать их старым ответом модели. При сбое диска могут остаться неизменяемые blobs без ссылок; state не должен стать частичным.

Стандартные проверки точных цитат, синтетичности и подтверждений не отключаются. Устаревший lab блокирует новое предложение. Обновлённая рекомендация снимает прежнее одобрение. Большие проекты требуют копирования blobs во временную папку: выигрыш времени не гарантируется при любом объёме.

`decision-card` создаёт exports/decision-card.html и JSON. На первом экране — вопрос, рекомендация, возражения, условия пересмотра и пробелы. Альтернативы, экономика и цитаты раскрываются по запросу. Это снимок, не интерактивное согласование. Устаревшие документы и ошибки целостности блокируют новую карточку. При ещё не одобренном выборе ожидаемое отсутствие финальной стратегии не мешает показать рекомендацию владельцу; другие ошибки не скрываются.

Техническое сравнение одной и той же подготовленной посылки выполняется `python tools/benchmark_checkpoint.py`. Оно проверяет совпадение содержательных хешей и отсутствие самоподписанного решения. Результат — checkpoint-benchmark.json. Этот замер не заменяет живое сравнение LLM, не доказывает лучшую стратегию и не измеряет стоимость токенов.
