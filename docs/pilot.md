# Пилот с фиксированным окном наблюдения

Оценка работает для двух независимых плеч, одного заранее заданного бинарного неблагоприятного исхода и горизонта, одинакового в обеих группах. Положительная разница означает меньше неблагоприятных исходов. Для сложных схем, повторных проверок без поправки, связанных наблюдений или подгрупп нужна отдельная статистическая постановка.

## Запуск

До поступления результатов владелец, аналитик и команда расчётов согласуют план. Зафиксируйте его отдельным источником.

```text
python -m strategist pilot plan projects/case protocol.json --id trial-plan
python -m strategist source add projects/case results.json --id trial-readout --title "Срез пилота"
python -m strategist pilot evaluate projects/case --plan trial-plan --results trial-readout --id trial-assessment
```

План содержит единицу счёта, аудиторию, исход, контроль, окно, порог пользы, условные значения базовой доли и мощности для выборки, порог операций, список критических случаев и финансовый горизонт. [Форма на примере](../examples/telecom-brief/pilot-plan.json).

Срез содержит возвращённый планом SHA-256, длину окна и признак заранее определённого момента чтения. В каждом плече указываются число назначенных, число завершивших окно, число неблагоприятных исходов и число неизвестных после закрытия окна. Незрелые также остаются неизвестными для результата по всем назначенным. Подтверждение оценки журналов, инцидентов и входных чисел фиксирует владелец данных. Числа пилота и происхождение данных не удостоверяются хешем.

Операции считаются по всем подтверждённым запросам. Для каждого критического случая из плана нужен явный счётчик. Даже при раннем чтении критический случай создаёт рекомендацию о паузе. Положительный вывод об охвате также требует проверки экономики. Экономика может быть неизвестной или включать нижний вклад и верхнюю оценку всех дополнительных затрат на том же горизонте. Допущение само по себе не открывает переход. [Пример среза](../examples/telecom-brief/observations/reconciled.json).

## Правило и пересмотр

В режиме всех назначенных инструмент рассчитывает наименьшее и наибольшее возможное снижение. Для нижней оценки все неизвестные в пилотном плече считаются неблагоприятными, все неизвестные в контроле — благоприятными. Для высокой оценки заполнение обратное. Два крайних расчёта получают интервалы Ньюкомба (метод 10). Внешние границы показывают чувствительность к пропускам и выборочную неопределённость при номинальном уровне, без гарантии точного покрытия. [Первичная статья Ньюкомба](https://pubmed.ncbi.nlm.nih.gov/9595617/).

После заданного момента чтения и полного окна обеих выборок нижняя величина эффекта должна быть не меньше заданного порога, а нижний край интервала выше нуля. Правило позволяет рассмотреть следующий охват при выполнении остальных проверок. Чтобы утверждать, что истинный эффект как минимум равен порогу, нужна отдельная более сильная статистическая граница. Момент чтения, достаточность событий, безопасность, сравнимость затрат и результат контроля рассматриваются по отдельности.

Результат сохраняется как производный источник с родителями «план» и «срез». Срез, добавленный раньше плана в проекте или с другим хешем, не проходит. Журнал доказывает порядок операций в этой папке. Пререгистрацию вне неё подтверждает владелец. Не переносите порог после просмотра результата. Новый протокол требует новой проверки с отдельными данными.

При исправлении сначала выполните `impact`, затем импортируйте новый срез и замените ошибочный через `source supersede`. Старые расчёты и claims перенесутся в историю и перестанут поддерживать действующее решение. Выполните новый расчёт с тем же планом, пересмотрите варианты и попросите владельца решить. Оценка не подтверждает запуск и не выполняет действий вовне.
